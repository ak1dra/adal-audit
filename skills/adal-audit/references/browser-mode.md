# Браузерный режим (когда скрипты не видят интернет)

Этот режим нужен, когда `check_access.py` вернул `"mode": "browser"`. Так бывает в песочнице claude.ai: код не может обращаться к goszakup.gov.kz и kaspi.kz. Сайты при этом открыты через браузер пользователя (Claude in Chrome, встроенный браузер Claude Desktop, computer use) или через инструмент получения веб-страниц, если он пускает на эти домены.

Собери данные браузером, сохрани их в два JSON-файла и прогони через тот же движок рисков и генератор Excel. Логику флажков руками не повторяй: так все отчёты считаются одинаково.

**Не переписывай таблицы вручную.** В `scripts/js/` лежат готовые скрипты для javascript-инструмента браузера. Они за один вызов возвращают JSON со всеми лотами (сотни строк) и ценами Kaspi. Сохрани результат в файл и передай скриптам. Вручную, через чтение страницы, работай только если javascript-инструмента нет; тогда реальный объём — около 50 лотов.

| Скрипт | Где запускать | Что вернёт |
|---|---|---|
| `scripts/js/goszakup_lots.js` | вкладка `old.goszakup.gov.kz` | все лоты по фильтру → `lots.json` |
| `scripts/js/kaspi_prices.js` | вкладка `kaspi.kz` | цены по списку `kaspi_query` → `kaspi.json` |

В начале каждого скрипта отредактируй константы (`FILTER`, `QUERIES`) и запусти его целиком.

## 1. Код места поставки (КАТО)
Открой `https://old.goszakup.gov.kz/ru/search/getKato?name=<город>` (например, `name=Актау`). В ответе JSON, возьми `id` нужного города или области.

## 2. Список лотов
Открой `https://old.goszakup.gov.kz/ru/search/lots`, подставь КАТО и даты в `FILTER` скрипта `goszakup_lots.js`, запусти его и сохрани вывод в `lots.json`. Пропусти остальную часть этого раздела, если скрипт отработал.

Ручной вариант: открой поиск (подставь значения, пустые параметры убери):
```
https://old.goszakup.gov.kz/ru/search/lots?filter[kato]=<КАТО>&filter[trade_type]=g
  &filter[start_date_from]=2026-10-24&filter[start_date_to]=2026-10-28
  &filter[name]=<товар>&filter[amount_from]=<мин. сумма>&count_record=50
```
- `start_date_to` — **на день позже** последнего дня периода: портал сравнивает с полуночью.
- `count_record` принимает только 50, 100, 500, 2000.
- `trade_type=g` — товары. Услуги (`s`) и работы (`r`) с Kaspi не сравниваются.

Из таблицы `#search-result` для каждой строки возьми:
- `lot_id` — колонка «№ лота»;
- `announce` — заголовок объявления;
- `customer` — текст после «Заказчик:»;
- `trd_buy_id` — число из ссылки `/ru/announce/index/<число>`;
- `lot_url` — полная ссылка на объявление;
- `name` — «Наименование и описание лота»;
- `qty` — «Кол-во»;
- `amount` — «Сумма, тг.», **это сумма без НДС**;
- `method` — «Способ закупки».

## 3. Отбор кандидатов
Сначала прогони только список, без деталей: так станет видно, какие лоты подозрительны.
```bash
python3 scripts/generate_excel_report.py --lots-json lots.json --include-medium --json candidates.json --output draft.xlsx
```
В `candidates.json` у каждого лота есть `kaspi_query` (у лотов без модели — `null`). Детально проверяй только первые 10–20.

## 4. Детали по кандидатам и крупнейшим лотам (страница объявления)
Открывай карточки **всех кандидатов и 10 крупнейших по сумме лотов**, даже если флажков нет. У крупных лотов модель часто указана только в ТЗ, а пустой реестр без этой проверки ничего не доказывает. Если в ТЗ нашлась модель или артикул, добавь в лот поле `kaspi_query` («вид товара + бренд + модель») и проверь цену в Kaspi.

- **Главная вкладка:** «Кол-во поданных заявок» → `bids_count`. Для закупки из одного источника — «Приглашенный поставщик», `bids_count: 1`.
- **`?tab=documents` → «Техническая спецификация» → PDF:** «Срок поставки» → `delivery_term`, описание → `spec_full`, ссылка → `techspec_url`. Если в тексте указан бренд или модель без слов «или эквивалент», это видно из `spec_full`.
- **`?tab=protocols` → «Просмотреть протокол» (PDF):** участники с ценой за единицу → `bidders: [{name, bin, unit_price}]`, победитель → `winner: {name, bin, unit_price}`, ссылка → `protocol_url`.

Допиши эти поля к лоту в `lots.json`. Отсутствующее поле не выдумывай, просто не указывай его.

## 5. Цены Kaspi
Открой `https://kaspi.kz/shop/`, впиши запросы в `QUERIES` скрипта `kaspi_prices.js`, запусти его и сохрани вывод в `kaspi.json`. Скрипт применяет те же правила совпадения модели, что и Python-версия.

Ручной вариант: для каждого `kaspi_query` из кандидатов открой `https://kaspi.kz/shop/search/?text=<запрос>`. Выбери карточку, где **совпадают модель или артикул и вид товара**. Если такой нет — `null`, «похожую» не подставляй. На карточке, во вкладке «Продавцы», возьми цены. Запиши в `kaspi.json`:
```json
{"картридж Xerox 106R02773": {"title": "…", "median_price": 3350, "min_price": 3188, "max_price": 4500,
                               "sellers_count": 8, "kaspi_url": "https://kaspi.kz/shop/p/…"}}
```
Медиана — средняя по порядку цена из списка продавцов.

## 6. Итоговый отчёт
```bash
python3 scripts/generate_excel_report.py --lots-json lots.json --kaspi-json kaspi.json --output goszakup_kaspi_audit.xlsx
```
Затем выполни шаг проверки из `agents/audit-reviewer.md` и отдай файл пользователю. **Отдавай Excel и при пустом реестре**: лист «Требуют ручной проверки» показывает крупные лоты, которые не удалось сверить по цене. Пользователь должен понимать, что «не найдено» не значит «всё чисто».

## Если нет и браузера
Попроси пользователя открыть ссылку поиска из шага 2 у себя и прислать страницу: сохранить как HTML, распечатать в PDF или скопировать таблицу. Распарси её в `lots.json` и продолжи с шага 3.
