# ADAL — ИИ-аудитор госзакупок РК (оркестратор)

Цель: дать комиссии **короткий реестр конкретных сомнительных лотов** с доказательной базой, а не общий отчёт обо всём.

```
1 Goszakup Auditor  → лоты по фильтрам: публичный реестр goszakup (без токена) или OWS API
2 Kaspi Checker     → рыночная цена по уникальным товарам (лимит --kaspi-limit, кэш 7 дней)
   Risk Engine      → флажки: Kaspi, межлотовое сравнение, процедурные; балл 0–100
   Enrich (портал)  → для кандидатов: полное ТЗ (PDF), срок поставки, участники и цена победителя
   Risk Engine      → переоценка по фактическим данным
3 Audit Reviewer    → ручная перепроверка топ-лотов, удаление ложных срабатываний
   Excel            → реестр сомнительных (балл ≥ 50, топ --top) + итоги по регионам
```

Флажок — **индикатор риска, а не доказательство**. Формулируй осторожно и не называй людей или организации виновными.

## 0. Проверь окружение (всегда первым)
```bash
python3 .claude/skills/adal-audit/scripts/check_access.py
```
Путь к скиллу может отличаться: в claude.ai это папка, куда загружен скилл. Ищи `scripts/check_access.py` рядом с этим SKILL.md.
- `"mode": "scripts"` — сайты доступны, работай по шагам 1–4 ниже. Недостающие пакеты поставь командой из поля `install`.
- `"mode": "browser"` — код не видит goszakup.gov.kz (так в песочнице claude.ai). **Не подставляй демо-данные и не сдавайся:** собери данные через браузер или веб-инструменты по `references/browser-mode.md` и прогони их через те же скрипты (`--lots-json`, `--kaspi-json`). Если браузера тоже нет, попроси пользователя сохранить страницу поиска (ссылку дай готовую) и прислать файл.

## 1. Уточни у пользователя (если не сказано)
- **Регион/город** (`--region Астана`, `--region Караганд`), **период** (`--from/--to`), **товар** (`--keyword ноутбук`), **мин. сумма** (`--min-amount`), **конкретные заказчики** (`--bins 123456789012,…` или файл).
- Не дали ничего — бери последний месяц (`--from`), `--limit 1000`, и скажи об этом. Регион обязательно уточни: по всей стране 1000 лотов — это лишь несколько дней.
- `--include-medium` полезен, когда высоких рисков мало. Средний уровень — в основном межлотовые отклонения, там часто разные единицы измерения.

## 2. Запусти пайплайн
```bash
pip install openpyxl pypdf      # один раз
S=.claude/skills/adal-audit/scripts
python3 $S/generate_excel_report.py --region Карагандинская --from 2026-07-01 \
  --min-amount 100000 --limit 1000 --live --json suspicious.json --output goszakup_kaspi_audit.xlsx
```
- **Источник лотов** (`--source auto`): без `GOSZAKUP_API_TOKEN` используется **публичный реестр** old.goszakup.gov.kz/ru/search/lots — токен не нужен. 1000 лотов загружаются за ~5 с, весь прогон с Kaspi занимает ~30–60 с. Регион ищется по справочнику КАТО портала («место поставки»). При наличии токена используется OWS API. `--demo` — демо-данные.
- Сумма лота на портале указана **без НДС**; для сравнения с Kaspi цена пересчитывается с НДС 16% (ставка РК с 2026 г., переопределяется через `KZ_VAT=0.12`).
- **Kaspi** опрашивается только по лотам с указанной моделью или артикулом (латиница+цифры, например `Epson L6291`, `75Ah`). Совпадать должны модель и вид товара (по названию или категории Kaspi). Лоты с общими названиями («Ноутбук», «Щебень») сравниваются с ценами других заказчиков.
- **Дозагрузка карточек** (`scripts/enrich_lots.py`, `--enrich-limit 50`): для кандидатов с баллом ≥ 25 скачиваются техспецификация (PDF: срок и место поставки, полное описание, проверка «или эквивалент» по тексту ТЗ) и протокол итогов (все участники с ценами, победитель; для закупок из одного источника — приглашённый поставщик и его цена). Нужен `pip install pypdf`. На один лот уходит ~3–5 с, результат кэшируется в `data/lot_cache/`.
- После дозагрузки оценка пересчитывается по **фактической цене победителя**: если план был завышен, а торги снизили цену до рынка, лот понижается (`PLAN_INFLATED_ONLY`). Если победитель дорог (`WINNER_OVERPRICED`) или цена не снизилась от плана (`NO_PRICE_DROP`), риск растёт. Возможная переплата считается по цене победителя.
- Прогон длиннее ~2 минут запускай в фоне.

## 3. Перепроверь топ (обязательно перед передачей комиссии)
Следуй `agents/audit-reviewer.md`: проверь первые ~20 лотов из `suspicious.json`, запиши `review.json`, перезапусти с `--review review.json`. Это главный шаг против ложных срабатываний.

## 4. Что сообщить пользователю
- Сколько проверено, сколько попало в реестр, возможная переплата.
- Топ-5 лотов: регион, заказчик, суть в одной строке с цифрами.
- Регионы и заказчики с наибольшим числом сомнительных лотов.
- Что не проверено: нет данных Kaspi, лимит, демо-данные.
- Путь к .xlsx.

## Excel
1. **Сомнительные лоты** — уровень, балл, регион, заказчик + БИН, **ссылка на лот**, цена, **ссылка на Kaspi** с медианой и числом продавцов, отклонение, переплата, «Основания (с цифрами)», «Что проверить» (чек-лист), выпадающий «Статус проверки», комментарий. Автофильтр, сортировка по риску, шкала справа.
2. **Параметры и итоги** — фильтры прогона, счётчики, разрез по регионам, топ-10 заказчиков.
3. **Методология** — флажки, веса, формулы, оговорки.

## Опции
`--include-medium` — добавить СРЕДНИЙ уровень; `--top N` — размер реестра (по умолчанию 100).

## Справка
- Флажки и правовая база: `references/kz_red_flags_catalog.md`.
- Детали агентов: `agents/goszakup-auditor.md`, `agents/kaspi-checker.md`, `agents/audit-reviewer.md`.

Ограничения: в публичном режиме фильтр `--from/--to` — дата начала приёма заявок, в API — дата обновления лота. Схема фильтров OWS GraphQL может отличаться — при ошибке `errors` сообщи текст пользователю.
